# 会话文件

## 它回答的问题

每个会话都会留下文件的痕迹：写下的笔记、改过的配置、交付的截图。想从对话里
翻回去，只能一层层翻工具调用。**会话文件**把这条线索一次收好，并在整个会话期间
保持更新。

标签页就在「对话」和「轨迹」旁边，只展示当前会话。刷新页面、断线重连、另开一个
浏览器标签，看到的列表都一样——因为答案由 Host 计算，再推送给每个客户端。

## 哪些文件会被收集

| 来源 | 显示为 | 说明 |
| --- | --- | --- |
| `write` | 首次出现记为**新建**，之后记为**修改** | 首次出现按新建处理 |
| `edit` | **修改** | 增删改文本的补丁 |
| `str_replace_editor` | `create` 为**新建**，其余为**修改** | 支持三个命令 |
| `present` | **交付** | 也会加入会话本身没写过的文件 |

每个条目保留最后一次触碰它的轮次；同一路径多次写入会合并成一行，所以改过十次的
文件只列一次，并显示最新轮次。

## 列表怎么读

- **搜索**匹配文件名、目录和交付描述。
- **筛选**可只看新建 / 修改 / 交付，每个筛选上的计数就是它会显示的行数。
- **行徽标**由彩色圆点加文字组成，不依赖颜色也能分辨状态：蓝色=新建，琥珀=修改，
  绿色=交付。
- **点击整行**在右侧预览里打开文件，不离开对话。
- **复制**取单个路径；**复制全部路径**取整个会话的列表，每行一个绝对路径，可直接
  粘进终端。

行按最近触碰排序。左侧的扩展名小标签按文件类别着色（代码、文档、图片、数据），
长列表也更容易扫读。

## 回收文件

行上的回收按钮让 Host 把文件移到系统回收站。请求会先对照本会话的文件索引，所以
按钮碰不到这次对话没产生过的路径；目标还必须是普通文件，目录和不存在的文件在移动
之前就会被拒绝。

回收站不可写时，文件会被改名到同卷的 `.trash/<时间戳>/` 目录，并写一份
`.rm-safe-manifest.json` 记录原路径、时间和原因。这个兜底是因为 Windows 上 DSH 的
工具进程以低完整性运行，回收站可能静默拒绝移动；插件绝不会退化成永久删除。

回收成功后，行仍留在列表里（事件日志仍提到该文件），但当前浏览器标签会把它标为
**已回收**并不再打开。标记存在标签页的 session storage 里：刷新仍在，换一个浏览器
标签则看起来和之前一样。

## 边界

列表有意只收录工具结果能证明的文件：

- shell 命令、构建、格式化工具直接写出的文件，除非会话用 `present` 显式交付，
  否则不会出现；
- 只经过 git 改动、没走受跟踪工具的文件不会出现；
- 其他会话或你在对话之外改动的文件不会出现；
- `apply_patch` 变体不计数：它给的是范围而不是文件，无法可靠区分新建与修改。

这些限制和内置的「变更文件」卡片一致。请把它当成「这次对话在做什么」的视图，
而不是文件系统审计。

## 实现方式

Host 侧注册一个名为 `sessionFiles` 的 Session projection。projection 重放已提交
的事件日志，把 `tool/call`、`tool/result`、`deliverables/presented` 折叠成一份状态，
只发布派生出的 `{ cwd, files }` 视图。浏览器侧通过
`useProjection("sessionFiles")` 读取，不自己解析原始事件。

因为折叠在 Host 侧：

- 刷新 Web GUI 会用同一份日志渲染出同一份列表；
- 同一会话的两个客户端看到相同的条目；
- 插件不落盘任何文件，也不上传任何内容——只传路径、状态、轮次和交付描述。

打开文件时按 Session 的标准文件地址构造链接，所以预览行为和对话里的文件链接
完全一致。

## 兼容性

面向 DSH `>=0.2.1-rc.3`，仅 Web GUI。如果右侧栏服务缺席，列表照常可用，点击行
会显示一条提示，而不是打开预览。Host 代码只在应用启动时加载一次，所以更新插件需要
重启桌面端；浏览器端刷新页面即可。
